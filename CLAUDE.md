# CLAUDE.md — Dotfiles Repo

GNU Stow-based dotfiles with layered shell config, XDG compliance, and cross-platform support (macOS, Linux distros, WSL).

## Shell Config Load Order

```
~/.bashrc / ~/.zshrc          (thin dispatchers — OS detection only)
  → common.sh                 (XDG dirs, PATH, editor, aliases)
  → darwin.sh OR linux.sh     (OS base; linux.sh includes SSH agent)
  → {ubuntu,fedora,rhel}.sh   (distro overlay, Linux only)
  → wsl.sh                    (Windows interop, if in WSL)
  → ~/.config/bash/.bashrc    (shell-specific config)
    OR ~/.config/zsh/.zshrc
  → ~/.config/shell/local.sh  (machine-local overrides, not in repo)
```

**Never add logic to the thin dispatchers.** They only detect OS and source files.

| Package | Path |
|---------|------|
| `shell` | Cross-platform shell config and OS overlays |
| `bash` | Bash dispatcher + `~/.config/bash/` |

Deploy all: `stow shell bash zsh git starship fzf nvim bat`

## Key Conventions

**XDG compliance** — all configs go under `~/.config`, history under `~/.local/state`, cache under `~/.cache`. Never write to bare `~`.

**Machine-local config** — create `~/.config/shell/local.sh` on each machine for anything not tracked in the repo (work tools, private aliases). This file is sourced last by `common.sh`.

**Cross-platform paths** — never hardcode absolute paths with usernames or platform-specific prefixes. Use `$HOME`, `$XDG_*` variables, or `brew --prefix` guarded by `type brew`.

**Catppuccin Macchiato** — the consistent theme across all tools (Starship, FZF, Bat, Neovim, fast-syntax-highlighting).

**Brew prefix caching** — `zsh/.zshrc` caches `BREW_PREFIX=$(brew --prefix)` once. Use `$BREW_PREFIX` throughout, never call `brew --prefix` inline.

## Adding a New OS Distribution

1. Create `shell/.config/shell/os/{distro-id}.sh` (match `$ID` from `/etc/os-release`)
2. The dispatcher auto-loads it — no other changes needed
3. Reference `linux.sh` for the base patterns to follow

## Adding a New Stow Package

1. Create `mypackage/` mirroring the home directory structure
2. Add to `PACKAGES_TO_STOW` in `install.sh`
3. Add to unstow commands in `uninstall.sh`
4. Add to README.md Available Packages table
5. Test: `stow -nv mypackage`

## Commit Convention

Follows [Conventional Commits](https://www.conventionalcommits.org/). Changelog is auto-generated by git-cliff — do not edit `CHANGELOG.md` manually.

Common scopes: `bash`, `zsh`, `shell`, `git`, `nvim`, `starship`, `fzf`, `bat`, `vscode`, `ci`, `install`, `docs`

**Do not add a `Co-Authored-By` trailer on commits to this repo.**

## Git Hooks (Lefthook)

ShellCheck and shfmt run on staged shell files at pre-commit. ShellCheck excludes SC1090, SC1091, SC2016, SC2148 — these are expected for a cross-platform dotfiles repo. Shfmt enforces 4-space indent, binary-op newlines, case indent.

Run `lefthook install` once after cloning to register the hooks.
